# S0: realism harness, targets and blinded test

S0 gives every other imaging and anatomy stream one reproducible yardstick. The same Python code measures real library runs and simulator captures, through the same 512-px pipeline (JPEG q72 or not). Pass bands are written once to `datasets/library/realism_targets.json`. A deterministic capture hook films the PCI lab without `requestAnimationFrame`. CPU gates in vitest track the motion and contrast gaps. A blinded drill pairs real runs with simulated runs filmed at the same angles.

The current renderer scores 133 of 229 metrics inside the real band on the matched pipeline (137 of 229 lossless); see [S0-baseline-scorecard.md](S0-baseline-scorecard.md). Every number S0 applies is sourced in [../facts/S0.md](../facts/S0.md).

## One command

```
bash scripts/realism/run_all.sh --library-only     # self-test, then measure the library (cached; about 15 min cold on 8 workers)
bash scripts/realism/run_all.sh --set s0base       # self-test, then score a capture set (184 s cold for 7 sequences, 433 frames)
```

Options are `--pipeline matched|lossless` (default `matched`), `--jobs N` and `--skip-selftest`. The scripts use the Python standard library and macOS `sips` only. They reuse `read_png_gray`, `read_npy` and `write_png_gray` from `scripts/angio_library/common.py`. Caches live in `datasets/tmp/realism/` and can be deleted at any time.

## Files and public API

### `scripts/realism/` (Python)

| File | Purpose |
|---|---|
| `imlib.py` | Loaders, decoding and fast operations (see below). |
| `metrics.py` | Every metric, as a port of the audit scripts. Each docstring names its source script and rule. |
| `sources.py` | Library runs and capture runs behind one `Run` interface (see below). |
| `views.py` | `family((primary, secondary))` with a 15-degree threshold, and the six `REFERENCE_VIEWS` (the plan's five plus RAO cranial). |
| `geometry.py` | Centre-line geometry and motion in mm: tortuosity band RMS, projected length, tree extent, landmark displacement and speed. Real targets from the anatomy audit's result files; simulator values from the capture metadata. |
| `selections.py` | The audit's run lists, and replays of its seeded random selections. |
| `measure.py` | Run-level measurements with a per-run JSON cache (see below). |
| `targets.py` | Measures the library and writes `realism_targets.json`, including `reproduction` and `jpegEffect`. |
| `report.py` | Scores a capture set (see below). |
| `make_clip.py` | `plan`, `build <set>` and `verify` for the drill clips. |
| `selftest.py` | Synthetic images with known answers (see Verification). |
| `jobs/library_jobs.json` | The audit's hand-picked polylines and scan lines, plus 4 catheter lines added by S0. `use: false` marks lines the audit did not quote. |
| `run_all.sh` | The single entry point. |

`imlib.py` handles:

- npz, PNG and sips JPEG decoding, with an atomic decode cache;
- the library's JPEG q72 round trip;
- `resample512`, the bilinear resample used by the audit;
- fast `box_mean`, which matches the audit's integral-image box mean to 1e-10;
- FFT, radial power spectrum and profile sampling.

`metrics.py` covers:

- noise: SD by grey level, dark/bright ratio, autocorrelation lags 1-4, NPS shape and temporal rho;
- run-start settling;
- texture terciles and the 256-px background spectrum;
- thin-line ridges;
- local contrast;
- contrast timing, and `arrival_features` (arrival at 30% of the rise, time above 50%, end level, arrival at frame 0; the audit's `summarise.py` definition on the harness signal);
- opacified area;
- heart rate;
- grey percentiles;
- field bands and straight edges;
- block-matching motion;
- `xtrack` cross-section tracking;
- vessel and catheter profiles;
- the hand-drawn border halo (`edge2`);
- `edge_auto`, a new automatic border halo.

`sources.py`:

- Profiles are named by dataset: `cd-ds`, `cd-main`, `cadica`, `angiocad`. Both CoronaryDominance subsets list the same system metadata, so they are not labelled by product line.
- `CaptureRun` crops the collimated field (detected from the mean frame), resamples bilinearly to 512, rounds to 8 bit and applies sips JPEG q72 for the matched pipeline. It also keeps the uncropped resample for the field-edge metric.
- `gather_set` moves the dev server's flat `<set>__*.png` files into `datasets/tmp/captures/<set>/`.

`measure.py` functions:

- `m_noise`
- `m_settle`
- `m_still` (texture, spectrum, automatic halo and ridges on the pre-contrast frame)
- `m_ridge`
- `m_sequence(run, fps, pre_k=2)` (timing, local contrast, opacified area, heart rate, block motion). `pre_k` is the pre-contrast frame for local contrast; `None` reports it as null. The default keeps the library cache key.
- `arrival(seq_result)`: arrival features from a cached sequence result, without re-measuring
- `m_still` and `m_field` return a method-level skip for runs shorter than the frame they need (one CADICA run has a single frame).
- `m_pct`
- `m_field`
- `m_job`

`report.py`:

- Scores a capture set against the targets and writes `datasets/tmp/realism/reports/<set>/scorecard_<pipeline>.{md,json}`, plus `datasets/tmp/realism_report.json`.
- Vessel, catheter, rib-margin and motion jobs for captures come from the projected geometry in the capture metadata, so no hand-picking is needed.
- Per-artery rows are split by view family. `target_for` takes the most specific target (artery and view, artery, view, neither) with at least 3 real runs; the band column names the source when it differs from the row.
- Local contrast before contrast uses `_pre_frame`: the largest k <= 2 whose coronary iodine is at most 1% of the peak, else n/a.
- Noise by grey level is scored against cd-ds, like the overall noise SD; the cd-main bands (the plan's flat 5-6 level curve) are attached to each row as `alt_target`.
- Fluoroscopy sequences (`spec.mode == "fluoro"`) are kept out of the cine rows and feed one rule row: fluoroscopy noise SD over cine noise SD at equal grey must exceed 1.
- Geometry rows: tortuosity in three bands, LM+LAD length and arc/chord, tree extent, landmark P10-P90 displacement and speed. Length and extent are compared only within their own view family.

### Generated data

- `datasets/library/realism_targets.json`: 1,765 targets. Each one is `{metric, pipeline, profile, artery, view, n, median, iqr, p10_p90, min_max, band, band_rule, indicative, unit, method, script, source_runs}`. Timing, arrival, local contrast, opacified area and block motion are split per artery and per (artery, view family); xtrack lines per (artery, view family) too. The file also contains:
  - the pipeline, profile and view-family definitions;
  - `temporalExclusions: ["angiocad"]`;
  - `reproduction`: 122 audit values recomputed, each with `tol`, `within_tol`, `within_5pct` and, where the tolerance is wider than 5%, `tol_reason`; plus one information-only row;
  - `jpegEffect`;
  - `geometryNotes` (catheter-trace noise floor);
  - `errors` (exceptions: none) and `skipped` (method-level skips: one single-frame CADICA run).
- `datasets/library/sim-clips/`:
  - `plan.json`: 30 real runs with their exact angles, frame counts, rates and heart rates;
  - `index.json`: the clips;
  - `<id>/fNNN.jpg`: library-encoded frames, 96 MB in total.

### `src/dev/xrayCapture.ts` (TypeScript, development only)

The pure functions have no WebGL and are safe in Node:

- `resolveSpec(spec)`: fills defaults that replay the PCI lab. `spec.profile` (optional) selects the imaging-system profile; `null` keeps the renderer default.
- `runParams(base, R, k, mode)`: the scene builder's parameters plus `mode`, `framesSinceStart` (warm-up frames 0..warmup-1 as their own fluoroscopy run, then 0.. for the run) and `profile`. Every frame of `simulateSequence` and of a capture uses it.
- `prepareScenario(id)`: builds the anatomy and the diseased tree exactly as `AngioPci` does.
- `sceneInputAt(prep, R, k, sink)`
- `simulateSequence(spec)`: one `SimFrame` per frame, with `t` exactly `t0 + k/fps`, the scene, the params and the scene builder's `place` function. It throws if the scene builder no longer hands `place` to `SceneInput.extras`, instead of guessing.
- `vesselTrack(spec, vessel, frac)`, `catheterTipTrack(spec)` and `motionStats(track)`: tracks in 512-analysis px, giving cross-vessel range, principal-axis range and steps. The 512 scale comes from `fieldBoxPx(params, res)`, which predicts the box `metrics.field_box` finds (square field: the whole canvas), and `to512` / `px512PerNative(res, box)`, which mirror `CaptureRun.to512` / `scale512`.
- `landmarkMotionMm(spec, artery)`: landmarks at 10-90% of the ostium-to-distal arc length, P10-P90 displacement and speeds in mm at the iso-centre.
- `arrivalFeatures(S, fps)`: port of `metrics.arrival_features`.
- `iodineAmount(scene)`, `iodineSeries(spec)` and `timingFeatures(S)`: a TypeScript port of `metrics.timing_features`.
- `findCatheter(tubes)`
- `findTarget(doc, metric, {profile, pipeline, artery, view})` and `inBand(v, target)`
- `pixelScale(cam, res)`, `projectPx`, `uvToPx`, `px512PerNative`, `to512` and `fieldBoxPx`
- `FIELD_FRACTION` (circular field only) and `SCENE_SOD_MM`
- `FINE_VESSELS`, `fineFrames(n)`, `FLUORO_COMPANION`

The browser functions:

- `capture(spec | spec[])`:
  - renders on its own detached canvas and `XrayRenderer`, after warm-up frames in fluoroscopy mode;
  - switches the renderer to capture mode (`setCaptureMode(true)`: synchronous auto-window read-back, run frames counted per render, recursion cleared at run start) and passes `framesSinceStart` on every frame, so slow uploads cannot restart a run (critique item 18). If `setCaptureMode` is missing it warns and still passes `framesSinceStart`;
  - reads each frame back synchronously with `readPixels` and computes its SHA-256;
  - POSTs `/__capture/<set>__<seq>_fNNN.png` (8-bit grey PNG) and `<set>__<seq>.meta.png`.

  The metadata file holds JSON in PNG bytes behind an `XCMETA1` header, because the endpoint accepts PNG only. It contains:
  - the resolved spec and C-arm angles;
  - timestamps and bolus times;
  - frame hashes;
  - milliseconds per frame;
  - per-frame annotations: the projected centre line and radius of every non-twig vessel, the catheter, rib margins on frames 0-4, and the iodine amount; full-resolution centre lines of LM, LAD, LCx and RCA on frames 0 and n/2;
  - `fieldBoxPredicted`, `px512PerNative`, `profile` and `captureMode`.
- `standardSpecs(set, {fluoro?})` and `REFERENCE_VIEWS`: the scorecard's six views (LAD in RAO caudal, RAO cranial, AP cranial and LAO cranial; RCA in LAO and RAO) plus, by default, a 40-frame fluoroscopy companion of RAO caudal without contrast.
- `registerCapturePass(factory)`: lets streams that add `AccumulationPass`es to the lab add them to captures too.
- `installXrayCapture()`: sets `window.__xrayCapture` to `{version: 2, capture, standard, drill, simulate, resolve, registerPass}`.
- Live-lab hook mode (`source: "pci-hook" | "fluoro-hook"`): drives `window.__pciDraw` or `__fluoroDraw` and the preset buttons or the `__sim` store. It is not deterministic, because the labs take their time from `performance.now()`. It exists to check that the offscreen path still matches the lab.

### `src/ui/angio/RealOrSimDrill.tsx`

The default export is the drill.

- **Pairing.** It pairs every clip with its real CoronaryDominance run and rejects a pair unless the angles match within 1 degree and the rates are equal.
- **Playback.** Both clips play on one clock, at the same size and through the same display path, in random left/right order. Nothing identifies either source before the answer. The two sources are memoised per trial and the player's load effect depends only on primitive keys (base and frame list), so typing in the reader field or answering does not reload frames, restart playback or flash the loading overlay. The reaction-time origin is set once per trial, on the first ready signal.
- **Input.** Keys 1/2 or the arrow keys answer; N goes to the next pair.
- **Results.** It shows overall accuracy with a Wilson 95% interval, accuracy per view family and mean reaction time.
- **Readers.** A reader field records a code for pooled studies.
- **Storage.** The log is kept in `localStorage`, with every access wrapped in try/catch, and can be exported as JSON or cleared.
- **Style.** Clinical Graphite classes throughout: `panel`, `panel-head`, `btn`, `btn-accent`, `chip`, `field`, `notice-*`, `stat`, `metric`, `kbd`.
- **Exports.** `wilson(k, n)` and `drillStats(log)` are exported for tests.

- **Targets file:** well-formed bands; every measurement-target family present; AngioCAD absent from temporal targets; every checked reproduction row within its stated tolerance, with a reason wherever that exceeds 5%; 12 headline values within a strict 5%; per-view, geometry and arrival targets present.
- **Capture invariants:** cranial and LAO sign; exact timestamps; warm-up frames in fluoroscopy; explicit `framesSinceStart` and `mode` per frame and `profile` pass-through; the predicted field box (square, circle, shutters) and the 512 scale; reference views plus the fluoroscopy companion; deterministic scenes and seeds; lab defaults.
- **Gap gates:**
  - LAD and RCA cross-vessel range and largest step (owner S3a);
  - catheter-tip range (owner S7);
  - first appearance, rise and end level of the iodine curve, contrast arrival at 30% of the rise and contrast in the first frame (owners S5 and S10);
  - LAD and RCA landmark displacement and median speed in mm (owner S3a).
  These are always measured and printed; they assert only with `REALISM_STRICT=1`.
- **Anatomy gates (owner S3b):** LAD/LCx climb over the first 20 mm (plan: at most bifurcation + 3 mm; asserted in strict mode), the LM Finet ratio printed beside the literature mean 0.678 (not asserted), and the capture's mm per 512 px within 15% of the library's 6F scale.

## Verification

- **`scripts/realism/selftest.py`: 28 checks on synthetic images, all passing.**
  - White-noise SD 2.94 for a true 3, with lag-1 autocorrelation of -0.005.
  - 2-tap noise lag-1 of 0.48 horizontally (true 0.5) and -0.01 vertically (true 0).
  - AR(1) temporal rho of 0.45 for a true 0.5.
  - A Gaussian line of FWHM 4 px measures 4.20 px with w80/w20 of 0.371 (true value 0.372).
  - A hollow tube shows a wall separation of 4.0 px.
  - Timing features, cross-section tracking (range 19.9 px for a true 20), field-box detection, the resample identity and the metadata PNG round trip all pass.
  - Geometry ports: a straight line has 0 tortuosity; a 12-mm sinusoid puts 4.7 deg in the 8-20 mm band and 1.4 in the 20-60 mm band; length and P10-P90 of known shapes; arrival frame and end level of a known curve.
- **Library reproduction: 122 of 122 checked audit values within tolerance** (121 within 5%; rho 0.084 against the published 0.08 is within its rounding). These cover:
  - noise, settling, texture and thin lines;
  - all eleven timing figures and the per-artery rise;
  - opacified area and heart rate;
  - field bands for all four sources;
  - grey percentiles for the six view families;
  - seven vessel profiles, three catheters and six motion lines;
  - tortuosity, projected length, NCC displacement and speeds, and LCA tree extents from the anatomy audit's result files.
  The contrast arrival from the harness signal (LCA 0.733 s, RCA 0.667 s) matches the audit's run_analysis figures (0.73-0.8 s, 0.67 s), although the signals differ.
  The `reproduction` section of the targets file prints audit and harness values side by side.
- **Determinism (re-run after the capture-mode fix, uploads on).** Four captures of one 8-frame spec with 4 warm-up frames gave identical SHA-256 for every frame: two with normal uploads, one with every upload delayed by 600 ms (longer than the renderer's 400 ms run-gap heuristic) and one without uploads. Timestamps are exactly `k/15` in the metadata. In vitest, `simulateSequence` returns `t === t0 + k/fps` exactly. (The first determinism check, before capture mode, was byte-identical only because every frame finished within 400 ms.)
- **Reproduction of the audit's renderer numbers.** The audit's 275 renderer frames, scored through this pipeline, give values inside the audit's published renderer ranges:

  | Quantity | Harness | Audit |
  |---|---|---|
  | Noise SD | 2.06-2.66 | 2.08-2.59 |
  | Dark/bright ratio | 2.44-2.95 (median 2.77) | 2.5-2.8 |
  | Lung band-pass RMS | 2.27-3.97 | 2.7-4.8 |
  | Thin-line pixels | 1.1k-3.2k | 1.0k-2.9k |

- **Vitest:** `npx vitest run src/render/xray/realism.test.ts` gives 34 passed and 14 strict-only skipped. With `REALISM_STRICT=1`, 10 gap gates fail as expected and 4 pass (first appearance, rise, no contrast in frame 0, LAD displacement in mm). The gate values have moved since the first report because other streams changed the anatomy and motion: for example LAD cross range is now 1.7 px and RCA 54 px (band 27.8-45.6).
- **Drill:** `make_clip.py verify` gives 30 of 30 clips with matching angles, rate and length, and identical JPEG quantisation tables to the paired real run. A 40-trial UI self-test in the browser logged 40 trials and computed the statistics. The UI was mounted in a separate tab, rendered both clips and showed the pair angles before the answer.
- **Typecheck:** `npx tsc --noEmit -p .` exits 0 and `npx tsc --noEmit -p tsconfig.app.json` shows no errors in the S0 files. (The root `tsconfig.json` has `files: []` and project references, so `-p .` checks nothing by itself; the app config is the one that type-checks `src`, test files included.)

## Performance

- **The lab:** zero per-frame cost. `xrayCapture.ts` is loaded only in development, by a dynamic import, and runs only when called. The drill is an ordinary section component and draws two 512-px canvases per animation frame from preloaded images.
- **Capture mode** (768 x 768, this Mac, baseline of 2026-10-05):
  - scene build: 0.7-2.0 ms per frame;
  - render plus synchronous read-back: 12-21 ms per frame. The read-back forces a GPU sync, so this is an upper bound on the renderer's GPU time.
  - 7 sequences (433 kept frames plus warm-up) took 20 s including PNG encoding and upload.
- **Python:**
  - library measurement: 1,879 tasks, about 15 minutes cold on 8 workers;
  - scorecard: 184 s cold for 7 sequences (433 frames) on the matched pipeline, under the 5-minute acceptance; 32 s for the lossless pass once frames are converted;
  - clip build: 30 clips, with crop, resample and encoding in parallel; about 70 s once the conversions are cached.

## Activating a gate (owning streams)

Gates are activated in the owning stream's own test file, as critique item 12 requires, with the threshold read from the targets file:

```ts
/// <reference types="vite/client" />
import { findTarget, motionStats, vesselTrack } from "../../dev/xrayCapture";
const doc = Object.values(import.meta.glob<{ default: unknown }>("../../../datasets/library/realism_targets.json", { eager: true }))[0]?.default as Parameters<typeof findTarget>[0];
it.skipIf(!doc)("LAD sweeps like real cine", () => {
  const t = findTarget(doc, "xtrack.motion-LAD.range_px", { pipeline: "lossless" })!;
  const m = motionStats(vesselTrack({ set: "g", name: "lad", view: "raocaudal", fps: 15, nFrames: 38, injection: null, warmup: 0 }, "LAD", 0.3));
  expect(m.crossRange).toBeGreaterThanOrEqual(t.band[0]);
  expect(m.crossRange).toBeLessThanOrEqual(t.band[1]);
});
```

For image metrics, capture a set, run `bash scripts/realism/run_all.sh --set <name>`, and quote the scorecard rows in the stream's wave notes.

## Known limitations

- **Hand-picked real samples are few.**
  - Vessel profiles come from 10 large and 6 small segments, catheter profiles from 3, rib margins from 2, endplates from 3.
  - Motion lines number 3 for the LAD, 4 for the RCA and 5 for the catheter.
  - The bands are observed ranges, and rib margins (n = 2) are reported as indicative only.
  - Lines the audit did not quote are kept with `use: false` but excluded from targets.
  - Larger samples need more hand-picked or automatically traced segments.
- **Measurement targets now covered, and how.** Tortuosity bands, projected length, tree extent, NCC motion in mm with per-vessel speeds, contrast arrival at 30% of the rise and fluoroscopy-noisier-than-cine are scorecard rows; proximal course and the Finet ratio are vitest anatomy gates. The real values for the geometry rows come from the anatomy audit's result files (9 traced runs, 6-14 masks per view), not from a re-run of its node tools, which need hand-placed waypoints; samples are therefore small and RCA extents have n = 1-2 (indicative). Simulator values come from the projected geometry (not from image tracing or NCC tracking), as in the audit.
- **Still not covered.** Transect branch counts (the audit kept no per-run result file), global respiratory or pan motion (a population share, not a per-run band), operator practice (angle grid, runs per study), and a pass band for the Finet ratio (the abstract gives a mean only).
- **Drill clips predate capture mode.** The 30 clips in `datasets/library/sim-clips/` were filmed with the earlier renderer and without `setCaptureMode`. Re-film them after integration with `x.drill("drill")` and `python3 scripts/realism/make_clip.py build drill`.
- **Three audit numbers have unknown run selections.** These are block-matching motion (n = 14), the background spectrum (n = 24) and local contrast (n = 13 / 8). They are re-measured on documented selections rather than reproduced. The re-measured medians differ from the audit's: local contrast pre-contrast is 29.1 against 30.8 for LCA, the background spectrum beta is 2.55 against 2.82 (cd-ds JPEG), and block-matching median motion is 3.3 px per frame against 5.0 (LCA, cd-ds JPEG). The audit's selection for these three cannot be recovered, so the bands come from the documented selections.
- **CPU gate scale.** Gates predict the field box from the parameters (`fieldBoxPx`); captures measure it from the image. For the lab's square field both give the full canvas. The capture scale is 0.280 mm per 512-px analysis px against the library's 6F scale of 0.3077 (9% finer); pixel targets are not rescaled for this, and the 6F guide measures 7.0 px against the real 7.0-9.75 px.
- **Live-lab hook capture** depends on the lab's preset button titles and is not deterministic.
- **The drill measures nothing until external readers use it.** The 40-trial self-test used random answers. The plan's criterion (about 50% correct with the 95% interval including 50%) needs experienced readers who did not build the simulator, each reading every pair once. The reader field and JSON export exist for pooling.
- **Python is single-threaded per run.** Library measurement takes about 15 minutes cold. Results are cached per run, keyed by method version and file stamp.
