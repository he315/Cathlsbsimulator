## How it fits together

1. The lab drives a `ReplayHost` through `RecordedSession.apply(cmd, tWall)` and `.step(dt, tWall)`. The session logs commands, the dt of every step, 10 Hz frames, host events, and host snapshots before every decision (injection, catheter or device exchange, cine start, inflation, deployment) and every 10 s. UI-side events (mentor utterances, plan, time-out, report) go through `session.event(kind, data)` and are marked `ext` (not reproduced by replay).
2. Each frame the lab builds a `MentorInput` and calls `engine.step(input)`; before an injection, inflation, deployment or device advance it calls `engine.preAction(action, input)` and blocks the action when `allow` is false. Utterances go to `MentorVoice` (caption and speech), `AttendingDrawer` and `session.event("mentor", utteranceData(u))`.
3. At the end, `assessAttempt(record, { facts, geometry, focus, dominance, plan, selfRatings, report })` gives metrics, coverage, mistakes, standards, the PEARLS model and the timeline lanes. `Debrief` and `ReplayTimeline` render them. A decision point's snapshot restores through `ReplayController.branch(dp, makeHost)`, which returns a live `RecordedSession` carrying the record prefix.
4. `saveRecording` keeps the last 50 attempts; `saveTakeHome` stores the "next time I will..." line, which `PreBrief` shows next case.

## Per-frame cost

- GPU: none. Nothing in S11 renders to WebGL; the replay frame is drawn by the existing renderer through the integrator's callback.
- CPU per frame: `MentorEngine.step` 0.8 µs; `segmentForeshortening` 2.8 µs, called only on a cine start or a view change; `ProcedureRecorder.sample` 0.24 µs (one 73-byte frame at 10 Hz). `RecordedSession.step` adds one host `sample()` at 10 Hz and a host snapshot every 10 s (a JSON copy of about 1 kB for the legacy host).
- Event-driven: coverage at the end of a cine run, about 1.3 ms per run on the real tree. `assessAttempt` once at the end of the case.
- Memory: about 440 kB of frames per 10 minutes; 50 attempts in IndexedDB is about 30 MB at most. Saving and listing read only the metadata index (about 100 bytes per attempt), so they do not slow down as storage fills.

```ts
class LabHost implements ReplayHost<{ rod: R; transport: T; dose: D; patient: P; clock: C }> {
  apply(cmd) { /* route HandCommand to the rod worker, PedalState to dose and imaging, SyringeCommand to transport, carm to imaging */ }
  step(dt) { rod.step(dt); patient.step(dt); transport.step(dt); dose.step(dt); clock.advance(dt); }

  snapshot() { return { rod: rod.snapshot(), transport: transport.snapshot(), dose: dose.snapshot(), patient: patient.snapshot(), clock: clock.snapshot() }; }

}
```

## Revision after review (wave 1)

- Store bridge injection quality: the legacy store's cine starts with its injection, so the bridge now reports `injectStartS: null` (`preContrastMeasurable: false`) instead of 0. `analyse` sets `CineRun.preContrastOk` (and `InjectionQuality.preContrastOk`) to `null` for such runs, and the debrief's injection-technique measure skips the pre-contrast check when it is `null`. Before the fix every run through the bridge failed pre-contrast, so any self-rating of 3 or more for injection technique was flagged as over-confident. The peak time is now measured from the store's live `bolus.intensity`; the fallback `LEGACY_BOLUS_MODEL.peakPhase` (0.3) is named and its origin (the store's `advanceBolus` envelope) is in facts/S11.md.
- `CineRun.preContrastOk` and `InjectionQuality.preContrastOk` widened from `boolean` to `boolean | null`. No code outside S11 reads them.
- Rule thresholds: every inline number in `rules.ts` moved to `MENTOR_PARAMS`; the oversize ratio is read from `ANALYSIS_PARAMS`; the 0.7 foreshortening trigger is listed in facts/S11.md with its reason for differing from coverage's 0.8.
- Integration of `MentorInput.targetForeshortening` and `targetSegment`: steps 1e and 2 above, with two helpers added so the lab needs no geometry code (`segmentForeshortening`, `segmentLabelAt`).
- Persistence: a `recording-index` store (IndexedDB schema v2) holds one small summary per attempt; saving, trimming and listing read only the index. `getAll` uses one transaction with bulk requests.
- Benchmarks: `importBenchmark` checks that `n` is a whole number, `mean` is finite, `sd` is finite and non-negative under `mean+sd`, `min` and `max` are finite under `max`, and every optional statistic is a number; the source label counts n over kept metrics only; `standardsFromBenchmark` keeps the critical-errors standard.
- Ownership: S11 edited only its own files in this wave and the revision (`src/mentor/**`, `src/ui/mentor/**`, `src/content/mentor/**`, `src/utils/idb.ts`, the two docs).

## Known limitations

- Replay of the current diagnostic lab: the store bridge gives a full timeline, metrics and debrief but not deterministic replay or rewind, because store actions are not logged as commands. Rewind-and-branch works with any `ReplayHost` (tested with `LegacyDiagnosticHost`); the lab needs to drive one through `RecordedSession`.
- `CardiacClock.restore` does not restore its random generator state, so a host in AF would not replay beat-for-beat. Sinus rhythm is exact. Owner of `cardiacClock.ts`: add the generator state to `snapshot()`.
- The legacy engine never produces `below-valve` or `deep-*` in a normal root with standard catheters; the analysis reads its `sinus-level` class (just above the valve) as "too low", and deep-engagement skill cards use the small-root library case with an Amplatz right.
- The legacy pressure model ignores ostial disease, so the "damping" preset does not damp in the legacy engine; S9's patient engine replaces it.
- Coverage scores a segment from the centreline geometry; it does not yet use lumen radius, the catheter's actual course, or motion across the cycle. The `catheter` field of `SegmentGeometry` is ready for the S7 rod centreline.
- Kerma and KAP columns are zero until S6's dose tracker feeds the frames.
- Thresholds other than the Jensen 2016 criterion and the two library measurements are model parameters awaiting expert calibration (facts/S11.md lists them).
- The demonstrator is deferred (wave 3). "Show me" is disabled in the drawer with its reason.
- Speech depends on the browser offering on-device voices; otherwise the component shows captions only and says so.
