# S8: hands, grips, pedals and input devices (wave 1)

S8 adds a framework-free input layer, `src/input/`, built on a small typed event bus. The layer turns mouse, trackpad, keyboard, gamepad, MIDI and USB (WebHID) input into the shared session contracts in `src/simulation/session/types.ts`: `HandCommand`, `PedalState` and `SyringeCommand`. It also adds two React views:

- `TableView`: the operator's table, drawn as equipment.
- `InputCalibration`: devices, calibration, gains, pedal test and a try-it table.

Following the stream brief, neither the layer nor the views are wired into the labs in this wave. The integration steps are below.

## Revision after review (2026-10-05)

An adversarial review asked for six fixes. All are done, each with a test:

| Review item | Fix |
|---|---|
| Rumble never went stale (medium) | `HapticsController` now ages the last reaction like `PseudoHapticGain`. Once it is older than `DEFAULT_PSEUDO.staleS` (0.3 s, model) the rumble mapper is stepped with `null`, so exactly one zero effect is sent and then nothing. `current()` returns the fresh reaction or null. `clear()` forgets the load at once. Turning rumble off while it buzzes also sends one zero effect. |
| Torquer brake held at the last level (low) | The brake comes from `haptics.current()`, so it drops to 0 when reactions go stale. The output report is sent only when its bytes change, at most once per 80 ms, except that releasing the brake is sent at once. `releaseAll()` releases it immediately. |
| `releaseAll()` missed gamepad, torquer, MIDI and USB holders (medium) | New `HandState.releaseAll()` opens the right hand (grip null, plunger 0) and unpins whoever holds the pin. `GamepadSource.releaseAll()` and `HidPedalSource.releaseAll()` latch every control that is still held (stick, triggers, bumpers, d-pad; torquer grip, pins, pedals, plunger), so it must be let go and pressed again before it acts. MIDI and USB switches need no latch: they only emit on change, and a later release from a source that no longer holds anything is ignored. |
| A pin could be released by a source that did not hold it (low) | The pin now keeps a set of holders, like the right-hand grip. It lets go only when the last holder releases. A release from a non-holder does nothing, even if it names the pinned target. Snapshots carry `pinHolders`; older snapshots with only `pinSource` still restore. |
| Port labels rendered below 12 px (low, design rule) | The labels sit above their stopcocks and are sized from the rendered scale: `labelFontSize(scale) = clamp(12.5 / scale, 12, 26)` user units. A `ResizeObserver` measures `min(width/1200, height/300)`; before the first measurement the scale is taken as `height/300`, which is right for a full-width strip. Above 14.5 user units the middle label moves up a line so neighbours do not touch. The labels render at 12.5 px at strip heights 200, 220, 240 and 300 (test). |
| HID learn could bind a constant status bit (low) | Learning now compares two real reports. The first report for a report id after opening is only a baseline. Polarity: a report seen before learning started is the rest state. Otherwise a following identical report marks a continuously reporting device (the first report was rest), and a following different report marks a device that reports only on change (the first report was the press). |
| Notes inaccurate (low) | TableView now rAF-coalesces the `hands` updates too (a ref plus the same `bump()`), so the performance statement holds. Integration step 1 now lists every legacy key and its conflict, including Space. |

No file outside the S8 ownership list was edited in this revision.

### Bus events (`InputEvents`)

- `hand: HandCommand`: for the device physics. Order and meaning:
  - `{grip, right, device}` when the fingers close on a device.
  - `{regrip, right}` immediately before it when the fingers close again on the same device without the hand moving away.
  - `{grip, right, null}` when the fingers open. Stored twist may then unwind through the hub.
  - `{grip, left, device}` followed by `{pin, device, on:true}` when the left hand pins a device.
  - `{pin, device, on:false}` followed by `{grip, left, null}` when it lets go.
  - `push` in mm at the hub (+ = advance). `torque` in rad at the hub (+ = clockwise, seen looking down the device from the hub).
- `pedal: PedalState`: the merged state, emitted on every change, inside the event that caused it.
- `syringe: SyringeCommand`: force 0..1 on the current port. Negative force with port `"aspirate"` draws back. Force 0 on release.
- `carm: CArmVelocity` and `table: TableVelocity`: velocity requests, summed across sources, with zero on release (dead-man).
- `hands: HandView`: emitted after any change, for the views.
- `blocked: BlockedEvent`: a motion was not passed on (`pinned`, `span`, `transition`, `absent`). Intended for sound and the mentor.
- `reaction: HapticFeel`: **inbound** from the physics.
- `sources: SourceStatus[]` and `calibrated`.

### Mapping

- **Push** = hand axial travel × push gain × pseudo-haptic gain.
- **Roll** = 2 × fingertip travel / D × roll gain × pseudo-haptic gain. D is the gripped diameter:
  - catheter hub 6 mm
  - torque device 8 mm (when fitted)
  - 0.014 in wire 0.3556 mm
  - 0.035 in wire 0.889 mm
  - rapid-exchange shaft 2 Fr
- **Spans.** Each grip has a push span and a roll span, centred on where the hand grasped. Motion beyond a span is clipped until the hand regrips.
- **Hand moves.** Moving between devices takes `switchMs` (300 ms). The hand arrives open.
- **Pins.** A pin blocks right-hand motion of the pinned device. The "auto" pin picks the usual partner:
  - right hand on a balloon, stent or imaging catheter: pin the wire;
  - right hand on a wire: pin the guide;
  - right hand on the catheter: pin the wire if one is present, else the sheath.
- **Optional wire drag.** `grip.emulateCoupling` makes an unpinned wire follow an over-the-wire device. This is for the legacy engine only; the rod physics produces drag from friction.
- **Encoder roll.** Roll from the torquer's rotary encoder bypasses the diameter, the span and the pseudo-haptic gain, because the knob is the hub.
- **Pin holders.** Several sources can hold the same pin (Q on the keyboard and the mouse right button both resolving to the wire). The pin lets go when the last of them releases; a source that does not hold it cannot release it.
- **Release all.** `InputSystem.releaseAll()` (pause, unmount, case end) releases every grip, pin, pedal, plunger and velocity, whichever source holds it, and forgets the haptic load. Controls still physically held are latched until let go once.
- **Stale reactions.** A hub reaction older than 0.3 s (model parameter `DEFAULT_PSEUDO.staleS`) counts as no load for every haptic channel: the pseudo-haptic gain relaxes to 1, rumble sends one zero effect and stops, and the torquer brake goes to 0.

## Verification

- `npx vitest run src/input/input.test.ts src/input/views.test.ts`: 86 tests pass (78 + 8).
- `npx tsc --noEmit -p tsconfig.app.json`: zero errors in `src/input/**` and `src/ui/lab/{TableView,InputCalibration}.tsx`.
  - `npx tsc --noEmit -p .` checks nothing, because the root tsconfig has `files: []` and only references other configs. The app config is the effective check.

What the tests establish, with numbers:

- **Mapping.**
  - 10 mm of hand travel gives a 10 mm push.
  - 3 mm of fingertip travel on a 6 mm hub gives 1.000 rad.
  - 4 mm on the 8 mm torque device gives 1.000 rad.
  - 1 mm on a bare 0.014 in wire gives 5.62 rad.
  - Gains, inversion and pseudo-haptic multipliers apply as specified.
- **Spans and regrip.**
  - A 30 mm push against a ±25 mm span delivers 25 mm and reports `span`.
  - Rolling 20 × 1 mm on the hub delivers exactly 4 rad (±12 mm span / 3 mm radius).
  - After a regrip the next 1 mm gives 1/3 rad again.
  - Commands on regrip are exactly `regrip` then `grip`.
- **Pins.**
  - A pinned wire receives nothing while the balloon advances 8 mm.
  - With coupling emulation on, an unpinned wire receives 5 mm of 10.
  - Pushing a pinned device emits nothing and reports `pinned`.
  - A new pin replaces the old one, and a stale key-up does not release it.
  - With Q (keyboard) and the mouse right button both holding the wire, releasing Q leaves the wire pinned; releasing the mouse button unpins it. A MIDI release that names the guide does not release a keyboard pin of the guide.
  - Snapshots carry every holder; a snapshot with only `pinSource` restores.
- **Release all.**
  - Gamepad: with the left stick deflected, LB and RT held, `releaseAll()` emits `{grip, right, null}` and `{pin, wire014, off}` and clears cine. Two more frames with the same pad held change nothing and push nothing. After the pad is let go and pressed again, grip, pin and cine return.
  - A latched trigger stays off at `pedalOff + 0.05` and acts again only after falling below `pedalOff`.
  - Torquer: grip, pin guide and fluoroscopy held through `releaseAll()` stay inactive (a 2 mm push in the same report moves nothing) until the buttons are let go once. Sequence tracking survives the latch.
  - `HandState.releaseAll()` on the syringe at force 0.7 emits force 0 and the unpin, and a second call emits nothing.
- **Grip switching.**
  - Halfway through the 300 ms move, the progress is 0.5.
  - Motion is blocked during the move, and the hand arrives open.
  - Absent devices are skipped.
- **Pedals.**
  - Keyboard, MIDI and torquer pedals all produce the same `PedalState` sequence.
  - Releasing a pedal emits `fluoro:false` inside the key handler, before any frame, so the beam stops within one frame.
  - Blur, gamepad disconnect and HID unplug release the pedals.
- **Latency.**
  - Mouse counts reach the command queue inside the event. 400 raw counts at the default 25.4/800 mm per count give 12.7 mm.
  - Held keys produce motion in the same `frame()` call.
  - Input-to-physics latency is therefore at most one frame.
- **Haptics.**
  - The pseudo-haptic target falls monotonically with force.
  - On a force step, the gain falls monotonically, and no 1/60 s step exceeds (1 − target)(1 − e^(−dt/τ)). It reaches the target within 1 s and relaxes back above 0.99 when reactions stop.
  - Rumble strong amplitude equals |axial| / 1.5. Snaps pulse at once. Updates are throttled to 80 ms. Silence is not repeated.
  - One reaction (axial 1.2) followed by 10 s of frames: the effects are at most ceil(300/80) + 1 = 5 sustained effects at strong 0.8, then exactly one zero effect, then nothing. Before the fix the review's probe of the same case played 120 effects at 0.8.
  - Torquer: one reaction at axial 1.5, then 1 s of frames, sends exactly two output reports, `[255,0,0,0]` then `[0,0,0,0]`. A fresh axial 0.75 sends `[128,0,0,0]`, and `releaseAll()` sends `[0,0,0,0]` at once.
  - With axial 3, a 25.4 mm mouse move pushes between 7.6 and 15.2 mm.
- **Calibration.**
  - 856 counts over 85.6 mm gives 0.1000 mm per count.
  - Implausible runs are rejected.
  - Calibration persists per device key through storage and survives a throwing or corrupt storage.
- **Views.**
  - Both views render without a DOM.
  - Hub wing geometry changes with roll and repeats at 2π.
  - The valve state and the device hub appear in the markup.
  - The table carries no digits in any text element.
  - Port labels: font size × rendered scale is at least 12 px at strip heights 200, 220, 240 and 300, and `labelFontSize` keeps 12 px down to a width-limited scale of 0.5.
- **HID learning.**
  - A first report with a constant status bit (0x80) followed by an identical report and then the pedal binds byte 1 mask 4 active-high, not the status bit.
  - A device that reports only on change (press, then release, with no earlier report) binds active-high.
  - An active-low switch with a resting report seen before learning binds active-low.
- **Visual check.** No browser was allowed for this stream. Table SVGs were dumped with `S8_DUMP=<dir> npx vitest run src/input/views.test.ts` and viewed through macOS Quick Look (guide setup, PCI with the wire pinned and the balloon gripped, diagnostic with the J wire in and blood in the syringe). Layout issues found this way were fixed:
  - the device hub overlapping the torque device;
  - oversized hands;
  - port labels over the tubing.
  - In the revision, the enlarged port labels were checked the same way at the default height (one row would have touched in the UI sans, so the middle label is staggered) and at a narrow strip (26 user units, staggered).

## Performance

Measured in `views.test.ts` on this machine, under Node:

- `InputSystem.frame()` together with a mouse event and a reaction feed costs **0.002-0.004 ms** across runs (0.003 ms in the first version). This includes gamepad polling, haptic filtering, HandState and the torquer report check.
- A full TableView render (server-side) costs **0.55-0.8 ms** across runs (0.84-1.06 ms in the first version).

TableView re-renders at most once per animation frame while commands arrive: `hand`, `syringe` and `hands` events all write to refs and call one rAF-coalesced `bump()`. The syringe preview runs its own rAF loop only while the host does not supply syringe contents and the plunger is pressed. A `ResizeObserver` updates the label size only when the strip is resized. It is SVG composited by the browser, uses no WebGL, and adds **no GPU passes**. The renderer's 15 frames/s at 768² budget is unaffected.

The torquer output report is now sent only on change (at most every 80 ms), not every frame, which removes up to 60 USB writes per second.

### 9. Calibration entry (S10 navigation)

### 10. Replay and telemetry (S11)

- Use `input.bus.onAny((type, payload) => …)` to record `hand`, `pedal`, `syringe` and `carm`.
- Use `input.hands.snapshot()` / `restore()` for rewind. The snapshot round-trips through JSON, and a restored state reproduces the same commands (test "snapshot").

## Known limitations

- **No browser check.** The pointer-lock, Web MIDI, WebHID and gamepad wiring is covered by unit tests with fakes and has not been run against real hardware. Points to check by hand:
  - Raw-count fallback on macOS Safari.
  - A sustain pedal.
  - A standard gamepad's trigger hysteresis and rumble.
- **Grip and arrival.** A held mouse button, key or stick during a hand move does not re-grip on arrival. The hand arrives open; this is deliberate.
- **Momentum filter.** It is a heuristic and can drop the last millimetres of a very smooth real deceleration. It can be turned off in settings.
- **Unsourced sizes.** Grip diameters for the hub, torque device and sheath, the travel spans, and all speeds are model parameters (see facts S8). The defaults need user tuning or a sourced measurement.
- **Force scales.** Pseudo-haptic and rumble force scales are in HubReaction "model units". They should be retuned once S7 publishes its force scale.
- **Wire drag.** `emulateCoupling` is a legacy fallback only and must stay off with the rod physics, or drag is counted twice.
- **TableView preview mode.** It integrates roll and insertion from commands, not from the device physics, so it shows command, not tip response. Hosts should pass `state.hubRollRad` and `state.insertedMm` from physics.
- **MIDI permission.** Web MIDI is not available in every browser (facts S8 F4b), and the device panel says so.
- **Keyboard-type USB pedals.** WebHID cannot read them (facts S8 F10). They work through the keyboard path.
- **HID learn polarity.** The polarity rule for a device whose first report arrives after learning starts is a heuristic. It fails only if a continuously reporting device's very first report already differs from its second (the pedal pressed within one report interval of pressing Learn); pressing Learn again fixes it.
- **Port labels on a narrow strip.** The label size is capped at 26 user units, so labels stay at 12 px or more only while the strip is drawn at a scale of 0.46 or more (a width-limited strip at least about 555 px wide). The labs are desktop layouts, well above this.
- **Port labels under the sleeve.** The labels sit above the stopcocks and are drawn under the gloves, like the manifold itself. When the right hand holds a rapid-exchange hub that lies above the manifold, the sleeve can cover a label, as it covers the manifold. The stopcock tooltips still name each port.
