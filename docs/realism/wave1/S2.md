# Wave 1, stream S2: detector, processing chain and field

Owner files: `src/render/xray/XrayRenderer.ts` (rewritten image chain), `src/render/xray/detector.ts`,
`src/render/xray/pyramid.ts`, `src/render/xray/systemProfiles.ts`, `src/render/xray/renderer.perf.ts`
(all new), this note and `docs/realism/facts/S2.md`. No other file was edited by S2.

The anatomy pass (data-driven `ANAT_FS` with `clutter()`), the bone pass, the tube pass (`buildTubes`
unchanged) and `addPass()` are kept as they were. Everything after the line-integral accumulation was
replaced. Every `ImageParams` addition is optional, so `sceneBuilder.ts`, `AngioPci.tsx` and
`FluoroView.tsx` compile and render unchanged.

## 1. What the chain does now

```
acc (RGBA32F when EXT_float_blend exists, else 16F): anatomy + bones + tubes + extra passes
 -> PRIM    exp(-P) x fluence: shutters (erfc penumbra, blade T 0.03), wedges (soft edge)  [mip-mapped]
 -> METER1  1 x 1: AEC meter signal and primary transmission at 5 central points
 -> DET     scatter = SPR x sum of 3 broad kernels of the *collimated* primary;
            N = Nm (Tp + S)/M with Nm = counts x (768/res)^2 x eta / settle^2;
            quanta noise sqrt(N) z1 + floor N sigma_f z2 (PCG3D hash, no lattice);
            sigma_f set per pixel from the previous frame's display slope (constant in grey),
            times the optional dark weighting exp(floorDarkSlope x (floorG0 - g) / 0.25)
 -> MTF x, MTF y   7-tap Gaussian on signal and noise together; white electronic noise; L = -ln(s)
 -> pyramid down G1..G5 (6-tap binomial), up R4..R0 (cubic B-spline at the exact 2:1 position):
            residual gain (harmonisation), band gains (read at the physical scale for this res),
            noise-adaptive soft coring
 -> METER   128 x 128 point subsample of the processed image + meter signal + primary transmission
            -> PBO + fence read-back, one frame late (synchronous in capture mode)
            -> percentiles p5/p50/p95 -> pivot-anchored two-slope window, 3-frame lag
 -> DISPLAY S-shaped LUT; motion-adaptive (3x3 motion detector) and, with a velocity buffer,
            motion-compensated recursion; field edge model; shutter display
 -> present plain copy at equal size, else separable Lanczos-3 to the canvas size
```

## 2. Public API

### `XrayRenderer.ts`

Existing exports are unchanged: `XrayCamera`, `ImageParams`, `XrayScene`, `XrayRenderer.create/resize/render/present/dispose/addPass/removePass`, and static `project`. `create()` also accepts an `OffscreenCanvas` (critique 12).

New optional `ImageParams` fields:

| field | default | meaning |
|---|---|---|
| `profile` | `"A"` | system profile (`"A" \| "B" \| "C"`) |
| `mode` | inferred (`recursive > 0.3` means fluoro) | fluoro takes the profile's recursion; cine takes `recursive` |
| `framesSinceStart` | inferred | frame index in the run. Settling restarts and recursion clears at 0 |
| `shutterPenumbraPx` | 6 | 10-90 % shutter penumbra in render px (at 768; scaled with res) |
| `wedges` | none | `{ angle, offset, transmission?, edgePx? }[]`, up to 4 |
| `gridIn` | true | false multiplies SPR by `GRID_OUT_SPR_FACTOR` (2.5) |
| `pulseWidthMs` | – | carried for motion-blur passes; the chain itself does not use it |
| `aec` | true | true: meter receives `counts`. false: `counts` = entrance quanta (thick paths get noisier) |
| `autoWindow` | true | false falls back to the old `window`/`level` mapping |

Changed meaning (backward compatible): `edge` 0.75 = the profile's nominal band gains (0 = no enhancement); `drc` 0.7 = the nominal residual gain (0 = none). `window` and `level` are used only when `autoWindow` is false or before the first metered frame. `counts` is in the scene builder's calibration units (cine 1500, fluoro 380) **per 768-reference pixel**: at another render size each pixel receives `counts x (768/res)^2`, so the noise per unit detector area is the same at every size (identical behaviour at 768, which AngioPci uses).

New exports, methods and members:
- `REFERENCE_RES` (768), `ResolutionPolicy`, `ResolutionState`.
- `fitCanvas(devicePx, policy?)`: render size = devicePx rounded up to a multiple of 32, capped at `maxRes` (1024); the frame is presented at the canvas size with a Lanczos-3 resample. Every `probeEvery` (90) frames `render()` is timed between two hard syncs; two consecutive probes over `budgetMs` (25) drop the cap to `fallbackRes` (768) for the session. Returns the render size. Callers that size the render themselves keep using `resize()`.
- `getResolution()`: `{ res, presentPx, fellBack, lastProbeMs }`.
- `perf: RendererPerf`: dev timing harness (below).
- `setProfile(id | null)`: override `params.profile`.
- `setCaptureMode(on)`: synchronous histogram read-back, run frames counted per render, recursion cleared at run start. With fixed seeds, captures are reproducible.
- `beginRun()`: force a run start on the next frame.
- `getVelocityTarget()`: `{ fbo, tex, res }`, an RG16F texture in px per frame, cleared to 0 every frame before the extra passes. The recursive filter samples the previous frame at `uv - v`.
- `getWindow()`: the window in force.
- `getMeter(): Promise<MeterReading>`: resolves with the next reading. `lastMeter` is the latest one, one frame late.
- `MeterReading = { frame, transmission (primary + scatter at the AEC points), primaryTransmission, p5, p50, p95, mean (processed log, high = dark), openFraction, window, runFrame, settle }`.
- Dev build only: `window.__xray` (latest renderer) and `window.__xrayPerf()` (timing table).

### Resolution independence (RAO caudal contrast run, 24 frames)

Noise per unit detector area, measured by `noise2.py` after an area-weighted resample to 512 (`s2area.py`), so the pipeline itself does not favour one input size:

| render | sigma_t median | lag-1 x / y |
|---|---|---|
| 768 | 3.04 | 0.28 / 0.42 |
| 1024 | 3.29 (+8 %) | 0.26 / 0.37 |
| 613 (not a multiple of 32) | 2.82 (-7 %) | 0.29 / 0.43 |
| `fitCanvas(900)`: render 928, Lanczos-3 to 900 | 2.99 (-2 %) | 0.32 / 0.43 |

Before the per-area scaling, per-pixel noise was fixed, so the same measure would have fallen with resolution; a first version of the scaling (floor converted with each size's own chain gain) gave 4.66 at 1024 and 2.24 at 613, which is why the floor is now converted with the 768 chain gain. Grey percentiles were 94/143-144/203 at all four sizes. Frames at 613 and 900 showed no seams or ringing.

Automatic fallback: `fitCanvas(1024, { budgetMs: 1, probeEvery: 2 })` dropped to 768 after the second over-budget probe (probe readings 15.5 and 18.4 ms at 1024, then 11.1-11.4 ms at 768) and kept presenting at 1024 through the Lanczos path, with no GL error.

### Cost

Test machine: Apple M4, WebKit with ANGLE-Metal, shared with about ten other agents (load varied by a factor of two to three within minutes; numbers below are from the same few minutes).

Per pass, serialised, `perf.enable(true, "finish")`, RAO caudal contrast run, 60 frames, medians net of the measured sync floor (0.4-0.6 ms):

| pass | 768 px, ms | 1024 px, ms |
|---|---|---|
| anatomy (not S2) | 11.1-11.5 | 8.5-15.3 |
| bones (not S2) | 0.4-0.5 | 0.5 |
| tubes, incl. `buildTubes` CPU (not S2) | 2.8-3.0 | 3.0-3.7 |
| primary | 0.2-0.3 | 0.3-0.4 |
| detector (incl. 1 x 1 meter pass) | 0.3-0.4 | 0.3-0.4 |
| MTF (2 passes) | 0.2-0.3 | 0.3 |
| pyramid down | 0.5-0.6 | 0.4-0.6 |
| pyramid up | 0.3-0.4 | 0.4-0.5 |
| meter + read-back | 0.0 | 0.0 |
| display | 0.6-0.7 | 0.5-0.8 |
| present | 0.0 | 0.0 |
| **S2 chain total** | **2.1-2.7** | **2.2-3.0** |

The serialised method overstates: each pass includes the CPU cost of issuing it, and the GPU clock drops while it idles between syncs, which inflates the first pass of a frame most (anatomy). The frame total therefore comes from a pipelined loop instead (60 pre-built scenes, `render()` back to back, one full read-back at the end), which bounds CPU plus GPU per frame:

| | 768 px | 1024 px |
|---|---|---|
| new renderer, ms per frame | 4.2-4.7 | 7.2-8.2 |
| original renderer, same minutes, ms per frame | 3.6-4.5 (earlier) / 6.4-7.3 (later) | 5.8-6.2 (earlier) / 7.1-7.9 (later) |

So the whole frame at 1024 is 7.2-8.2 ms on the M4, against the plan's 8 ms; the S2 chain's share is about 2-3 ms serialised and within machine noise pipelined. Extrapolated to a GPU 3-4 times slower, 1024 needs 22-33 ms, which is why `fitCanvas` probes and falls back to 768 above 25 ms (768: 13-19 ms at 3-4 times slower). Both are inside the 66.7 ms needed for 15 frames/s. The anatomy pass (clutter, S4) is now the largest single cost.

CPU per frame added by S2: about 0.3 ms (uniforms, sorting about 9.5k floats for the percentiles). `noiseFactors` takes about 50 ms per new gain set; it is cached and pre-computed at `resize()` for the default profile's cine and fluoro gains, at the render size and at 768 (the floor uses the 768 gain). The frame-time probe adds one stall every 90 frames when `fitCanvas` is used.

On this WebKit build the timer-query extension is exposed but its per-pass sums (70 ms) exceed the measured frame wall time (12.7 ms); the harness now detects that by itself and prints a warning.

  | plain window (`toneRatioMax` 1) | 17.1; 160 | 22.2; 119 |
  | `p50Band` [129, 145] | 13.3; 144 | 26.0; 127 |

  None restores RAO caudal without breaking the per-view p50 or overshooting LAO cranial, so profile A keeps `residualGain` 0.42 and `toneRatioMax` 2.5. Re-tune these (and consider `p50Band`) after the anatomy and clutter work settles (critique items 2 and 23); the variants above are one-line profile changes.
- **Per-view median grey.** RAO caudal p50 is 143 against the real 132, and AP cranial 137 against 129 (both inside the overall 129-145). The window targets are the same for every view; the residual differences come from the anatomy's grey distribution.
- **Pair-0 settling is 1.41 against 1.48 real.** The first frame of a run has no recursion partner and its window is solved on its own noisier histogram. Pairs 1-9 match within 0.04.
- **Floor scaling lags one frame.** The floor is constant in display grey (with the mild dark weighting) because its per-pixel amplitude uses the previous frame's tone slope and grey. A moving edge therefore sees a one-frame-old slope.
- **Motion adaptivity changes the noise tails.** It gives a slightly leptokurtic distribution in fluoro: kurtosis 3.3, against 3.0 without recursion. The 3 x 3 motion detector avoids the dark specks a per-pixel detector gave.
- **No velocity yet.** Nobody writes the velocity buffer, so recursion is motion-adaptive only (critique 19: no analytic anatomy velocity).
- **Collimated areas are dark and very noisy.** That is physically consistent at blade transmission 0.03. Processing sees the field with the blade attenuation removed, so shutter edges do not ring through the band filters.
- **Scatter is simple.** Kernel superposition on mip levels, with a fixed SPR from the caller and no thickness or kV dependence (S6 supplies `spr`). The scatter fit to catheter depth needs S2b and S5.
- **Resolution.** The image per unit area is within 8 % between 613 and 1024 px (table above). The pyramid has a fixed 6 levels, so at 1024 the coarsest band reaches a 25 % smaller physical scale than at 768; band gains are interpolated to the physical scale but the residual level is not. The Lanczos present can ring slightly at the field edge when upscaling a fallback 768 render into a larger canvas.
- **Timing on this machine.** The serialised per-pass numbers overstate GPU time (see Cost), and the timer-query extension's numbers are not plausible on this WebKit build; the harness flags that case. Use the pipelined loop for frame totals.
- **The late spectral task was not attempted.** That is the wave-2 `spectral.ts`, which is not in this stream's file list.
- **Profiles B and C share some of A's settings.** They use A's settling fit and A's p50 target, because neither was measured on those libraries, and neither has the dark-weighted floor (no dark/bright target was measured for them).

        sd = math.sqrt(sum(v * v for v in nd) / len(nd) / 2)
        ex.append((sum(mv) / max(1, len(mv)) - sum(st) / len(st)) / sd); sds.append((len(mv), round(sd, 2)))
    print(tag, "ghost excess (noise SD units) per frame:", [round(v, 2) for v in ex], "median", round(sorted(ex)[len(ex)//2], 2), "moving px, sd:", sds[:3])

"""noise2.py 'cap' analysis with an area-weighted (box-integral) resample to 512 instead of bilinear
point sampling, to compare renders at different resolutions per unit detector area."""
import sys, json, array
sys.path.insert(0, "/Users/qc25212/Downloads/Misc/Games and apps/Cath Simulator/docs/realism/research")
import imlib, noise2
def area512(img, w, h, margin=0):
    s = w / 512.0
    # 1-D box weights per output index
    def weights(n):
        W = []
        for o in range(512):
            a, b = o * s, (o + 1) * s
            ws = []
            i = int(a)
            while i < b and i < n:
                lo, hi = max(a, i), min(b, i + 1)
                if hi > lo: ws.append((i, (hi - lo) / s))
                i += 1
            W.append(ws)
        return W
    Wx = weights(w); Wy = weights(h)
    tmp = [array.array("d", [0.0]) * 512 for _ in range(h)]
    for y in range(h):
        row = img[y * w:(y + 1) * w]; t = tmp[y]
        for o, ws in enumerate(Wx): t[o] = sum(row[i] * c for i, c in ws)
    out = array.array("d", [0.0]) * (512 * 512)
    for oy, ws in enumerate(Wy):
        for ox in range(512): out[oy * 512 + ox] = sum(tmp[i][ox] * c for i, c in ws)
    return out
imlib.resample512 = area512
for rid in sys.argv[1:]:
