# S11 facts: mentor, telemetry, metrics, debrief and replay

This file lists every constant in `src/mentor/**`, `src/content/mentor/**` and `src/ui/mentor/**` that comes from outside the code, with the source that was opened in this stream. Quotes are short and verbatim. Values that are not listed here are model parameters and are named as such in code comments (see the last section).

## Literature opened in this stream

Opened at https://eurointervention.pcronline.com/article/virtual-reality-training-in-coronary-angiography-and-its-transfer-effect-to-real-life-catheterisation-lab

| Use in code | Quoted |
|---|---|
| `standards.ts DIAGNOSTIC_FULL_STUDY`: `standardisedLoops >= 8`, `procTimeS < 600`, `fluoroS < 180`, `contrastMl < 50` (strict `<` as in the text) | trainees had to perform "a complete CA with eight standardised cine loops in less than ten minutes, fluoroscopy time less than three minutes and using less than 50 ml of contrast" |

### Walsh et al. 2009 and Hatala et al. 2014: terminal versus concurrent feedback

Walsh CM, Ling SC, Wang CS, Carnahan H. Concurrent versus terminal feedback: it may be better to wait. Acad Med. 2009;84(10 Suppl):S54-S57. doi:10.1097/ACM.0b013e3181b38daf.
Opened at https://academic.oup.com/academicmedicine/article-abstract/84/Supplement_1/S54/8353508

- "Thirty novice endoscopists ... received feedback either during (concurrent) or after (terminal) each of their 12 practice trials."
- "At transfer, the terminal feedback group performed significantly better"; "The concurrent feedback group's performance decreased significantly on the transfer test".

Hatala R, Cook DA, Zendejas B, Hamstra SJ, Brydges R. Feedback for simulation-based procedural skills training: a meta-analysis and critical narrative synthesis. Adv Health Sci Educ. 2014;19(2):251-272. doi:10.1007/s10459-013-9462-8. PMID 23712700.
Opened at https://www.ebi.ac.uk/europepmc/webservices/rest/search?query=TITLE:%22Feedback%20for%20simulation-based%20procedural%20skills%20training%22&resultType=core&format=json

- "pooled effect size favoring feedback for skill outcomes of 0.74"
- "Terminal feedback appears more effective than concurrent feedback for novice learners' skill retention."

Use in code: the design choice in `mentor.ts` that non-safety feedback during a case is rationed and the rest deferred to the debrief. No number from these papers is used; the per-minute budgets are model parameters.

## App conventions reused (not literature)

- `coverage.ts viewFamily`: the thresholds of `standardView()` in `src/ui/angio/library.ts` (|primary| < 15 is AP, |secondary| >= 15 is cranial or caudal, LAO >= 70 is lateral). A standardised loop is one diagnostic run per side and view family.
- Trauma rates in `hosts/legacyDiagnostic.ts` are copied from `useSimulatorStore.ts` so the replay host and the store agree.
- `ANALYSIS_PARAMS.landingMarginMm = 1.5` matches the margin in the existing PCI debrief (`angioPci.ts debrief`).
- `bridge/simulatorStore.ts LEGACY_BOLUS_MODEL.peakPhase = 0.3`: copied from `advanceBolus()` in `src/state/useSimulatorStore.ts`, whose opacity envelope rises linearly to its maximum at lifecycle phase 0.3 and holds until 0.55 (`if (phase < 0.3) env = phase / 0.3; else if (phase < 0.55) env = 1`). It is a property of that store's model, not a physiological value. The bridge normally measures the peak from the store's live `bolus.intensity` (first phase at maximum opacity); this constant is only the fallback when intensity is not exposed. The store's bolus also starts with the injection, so the bridge reports pre-contrast filming as not measurable (`injectStartS: null`) instead of zero, and the injection-technique measure skips that check for those runs.
- Pre-brief teaching restates `data/catheters.ts`, `data/viewPresets.ts`, `data/teachingText.ts` and `simulation/angioPci.ts` content. No numeric clinical threshold was added.

## Model parameters (named in code, awaiting expert calibration)

- Coverage: `minForeshortening` 0.8, `maxOverlap` 0.25, `overlapMm` 2.0, `overlap3dMm` 8, `minViews` 2, `distinctViewDeg` 20.
- Analysis: `pushResistance` 0.6, `pushMinS` 1.0, `ignoredWarningS` 5, `withdrawMm` 0.5, `tooHighTorqueRad` 1.0, `wrongRotationRad` 0.35, `wrongRotationWindowRad` 1.2, `overRotationRad` 0.5, `earlyChangeAttempts` 2, `lateChangeAttempts` 4, `reversalDeadbandRad` 0.05, `minPostPeakCycles` 1, `oversizeRatio` 1.1.
- Attending: the ladder table per mode and severity, `escalateEveryS` 6, non-safety budget per minute by entrustment (3, 2, 1, 0.5, 0), each rule's `persistS` and `cooldownS`.
- Attending thresholds, `rules.ts MENTOR_PARAMS`: `pushStopS` 3 (pushing this long makes a further advance a take-over), `seatedNoAspirateS` 2, `septalStopS` 2, `foreshortenedTrigger` 0.7 (the attending speaks during cine when the target segment's projected/true length is below this; deliberately below the coverage adequacy threshold `minForeshortening` 0.8, so the attending interrupts only for a clearly foreshortened view and borderline views go to the debrief), `timeoutNoProgressS` 60 and `timeoutReapproaches` 3 (the plan's time-out defaults). `oversizeRatio` is not a separate value: it is read from `ANALYSIS_PARAMS.oversizeRatio` so the live attending and the debrief metric agree.
- Store bridge: `BRIDGE_PARAMS.viewRestS` 0.5 s (the C-arm must rest this long before its position counts as a chosen view).
- Skill cards: durations (60-180 s), the budgets of the efficiency cards (90 s fluoroscopy, 30 mL contrast), the ledger decay constant of 14 days (the plan's value).
- Expert benchmark rule (`mean`, `mean+sd` or `max`), chosen locally and shown in the UI.
- Telemetry: 10 Hz sampling, 10 s keyframes, column resolutions, 50 stored attempts.
- Expert benchmarks always keep the zero-critical-errors standard, marked critical and labelled simulator default, unless the benchmark itself measures `criticalErrors`.

## Not used for lack of an opened source

Heparin dose per kilogram, ACT targets, contrast-volume formulas and PCI passing criteria. The PCI standard set is labelled `simulator-default` throughout; the heparin field in the plan is the learner's own commitment with no "correct" value.
