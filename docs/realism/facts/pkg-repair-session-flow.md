# repair-session-flow: model parameters

The session plumbing that the procedure packages of build run 3 needed: the module gate hook, the attending and log API for modules, the postponed-case end path, the time-lapse hold for emergencies, team punctures in scenario start states, and module tip contexts in the case tips panel (`src/simulation/session/caseSession.ts`, `src/simulation/session/modules/index.ts`, `planning.ts`, `emergencies.ts`, `hypotension.ts`, `src/state/useProcedureStore.ts`, `src/ui/access/caseTips.ts`). No dose, threshold or device dimension was added. Everything below is a MODEL PARAMETER: a session, clock or panel setting with no clinical source.

| Parameter | File | Value | Unit | Rests on |
|---|---|---|---|---|
| `MP_SESSION.stopRepeatS` | caseSession.ts | 5 | s | A module's refusal (gate) said again within this time is not repeated, so a second click on a refused needle does not add a line. The planning module used the same 5 s for its own stop lines (`MP_PLANNING_TIME.repeatStopS`), which it now passes to `session.say()` |
| `holdLapse(by, rate)` default rate | caseSession.ts | 0 | times the wall clock | A held femoral compression, band or recovery time-lapse is paused unless the holder asks for a slower background rate. The emergencies module pauses it |
| Which lapses can be held | caseSession.ts `spend(..., long)` | manual compression (`femoralManual`), a failed closure device's compression, `holdCompression`, the recovery observation (`observe`, which also carries the band's time) | n/a | The design's 'femoral compression and band time-lapse'; short steps (an order, a sheath, a chart item) are never held |
| `lapseHoldsOn` | caseSession.ts | false by default; true in the live lab (useProcedureStore) | n/a | A session built for a test or played by the autopilot keeps every lapse running through, as before, so the episode scoring the earlier emergencies tests pin is unchanged |
| `MP_EMERGENCY_LAPSE.resumeAfterRecoveredS` | modules/emergencies.ts | 60 | s | A held lapse goes back on the clock once the heart rate has been at or above `MP_EMERGENCIES.symptomaticHr` and the mean pressure at or above `MP_EMERGENCIES.persistMapMmHg` (both existing parameters) for this long. A reaction is held at least through `MP_EMERGENCIES.imWithinS` (the IM adrenaline window) plus this time, and a faint from its onset for at least this time, so the learner meets it as it begins and not once the numbers are already low |
| Hold inside a tick's lapse slice | caseSession.ts `tick()` | the slice runs in steps of at most 5 s; a hold that begins in one takes the unspent part | s | The patient's own 5 s steps (`advanceClock`); an emergency seen in one step does not play on for the rest of the slice (`MP_SESSION.lapsePerTick`) |
| A held lapse is still open | caseSession.ts `finish()`, `observe()`, `femoralManual()`, `femoralDevice()`, `holdCompression()` | the case does not finish, and no second long lapse is queued, while a lapse is held | n/a | The held compression's end (the closure and its delayed complications) has not run yet |
| `CASE_MODULE_TIPS` | ui/access/caseTips.ts | 3 | tips per module context | A session module's context (its screen open now, such as the right heart numbers) keeps this many of its best tips at the top of the case tips panel, inside the panel's total. The right heart context has four haemodynamic tips at the same score, with haemo-wedge-oedema-risk the third in registry order, so one or two would not show it |
| Postponed-case logbook row | state/useProcedureStore.ts `POSTPONED_NOTE`; caseSession.ts `finish()` summary `passed` | never a pass, with a note; the summary's `passed` is false too, so the debrief agrees with the row | n/a | A case postponed at the chart review before any puncture did no access, so it is logged with its decisions but is not access-EPA evidence (as a case opened past 'access' is not) |
| 'Before any puncture' | caseSession.ts `postponement()` | no puncture hook yet, no site with a sheath or a first skin pass | n/a | Only such a postponement ends the case without a closed site; a postponement after a puncture still needs the site closed |
