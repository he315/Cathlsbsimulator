# S8 facts: hands, grips, pedals and input devices

Each fact below was read from the page given, during this stream (October 2026). Quotations are short extracts; the code comment that uses each fact cites its id (for example "facts S8 F4").

Every other number in `src/input/**`, `src/ui/lab/TableView.tsx` and `src/ui/lab/InputCalibration.tsx` is a model parameter. Those are listed at the end of this file and are marked "model" in the code.

## Browser APIs

**F1. Pointer lock and raw mouse counts.** Source: https://developer.mozilla.org/en-US/docs/Web/API/Element/requestPointerLock
- `unadjustedMovement`: "Disables OS-level adjustment for mouse acceleration, and accesses raw mouse input instead. The default value is `false`."
- "Transient activation is required when calling `requestPointerLock()`."
- The method returns a Promise. Success and failure are reported through the `pointerlockchange` and `pointerlockerror` events.
- Used in `pointerLockMouse.ts`: the lock is requested inside the mousedown handler, and a separate "mouse:os" calibration is kept for when raw counts are refused.

**F2. movementX units are not fixed.** Source: https://developer.mozilla.org/en-US/docs/Web/API/MouseEvent/movementX
- "Depending on the browser and operating system, the `movementX` units may be a physical pixel, a logical pixel, or a CSS pixel."
- This is why mm per count is measured per device and per mode, and why the 800 counts-per-inch default is labelled a model parameter.

**F3. Gamepad standard layout and rumble.** Sources: https://w3c.github.io/gamepad/ and https://developer.mozilla.org/en-US/docs/Web/API/GamepadHapticActuator/playEffect
- Buttons 4 and 5 are the left and right bumpers ("front top"). Buttons 6 and 7 are the left and right triggers ("front bottom").
- Buttons 12-15 are the top, bottom, left and right of the left cluster (the d-pad). Buttons 0-3 are the bottom, right, left and top of the right cluster.
- Axes 0/1 are the left stick and axes 2/3 the right stick. Negative is left or up, positive is right or down.
- "All button values MUST be linearly normalized to the range [0 .. 1]." The `mapping` attribute is "standard" for this layout.
- `playEffect("dual-rumble", {duration, startDelay, strongMagnitude, weakMagnitude})`: durations are in ms and magnitudes run 0.0-1.0. The promise resolves "complete" or "preempted".

**F4. MIDI pedals.** Sources: https://midi.org/midi-1-0-control-change-messages and https://midi.org/summary-of-midi-1-0-messages
- Controller 64 is "Damper Pedal on/off (Sustain)", with "≤63 off, ≥64 on". Controller 66 is "Sostenuto On/Off" and controller 67 is "Soft Pedal On/Off", with the same thresholds.
- Controller 11 is the "Expression Controller" and controller 4 the "Foot Controller", each 0-127.
- Control change uses "Status Bytes 176-191" (0xB0-0xBF). Note Off is 1000nnnn and Note On is 1001nnnn.
- The summary page does not state that a Note On with velocity 0 means Note Off. The code treats it as a release by its own reasoning (a zero-velocity press cannot be a press), not on the strength of this source.

**F4b. Web MIDI permission.** Source: https://developer.mozilla.org/en-US/docs/Web/API/Navigator/requestMIDIAccess
- "This feature is available only in secure contexts (HTTPS)". `sysex` defaults to `false`. The call "may prompt the user for access".
- Errors include `NotAllowedError` and `NotSupportedError`.

**F5. Wheel delta units.** Source: https://developer.mozilla.org/en-US/docs/Web/API/WheelEvent/deltaMode
- `DOM_DELTA_PIXEL` 0x00, `DOM_DELTA_LINE` 0x01, `DOM_DELTA_PAGE` 0x02. "Do not assume that those values are specified in pixels."

**F10. WebHID.** Sources: https://developer.mozilla.org/en-US/docs/Web/API/HID/requestDevice, https://developer.mozilla.org/en-US/docs/Web/API/HIDInputReportEvent and https://developer.chrome.com/docs/capabilities/hid
- requestDevice: "Transient user activation is required." It is "available only in secure contexts". Filters take `vendorId`, `productId`, `usagePage` and `usage`.
- HIDInputReportEvent: `data` is a DataView that excludes the report id. `reportId` is "0 if the HID interface does not use report IDs".
- Chrome: "if a top-level collection has a protected usage (e.g. generic keyboard, mouse), then a website won't be able to send and receive any reports defined in that collection."
- This is why keyboard-type foot switches go through the keyboard path (F and C).

**F11. Vendor-defined HID usage page.** Source: https://docs.rs/hut/latest/hut/ (built on HID Usage Tables 1.5)
- "Represents a Vendor Defined Page number value of in the range `0xFF00..=0xFFFF`."
- The DIY torquer uses usage page 0xFF00, usage 0x01. The report layout is our own specification (see `hidPedals.ts`); it is not taken from any product.

## Units and sizes

**F6. French catheter scale.** Source: https://en.wikipedia.org/wiki/French_catheter_scale
- "1 French (Fr) defined as 1⁄3 millimeter". Used in `frToMm`.

**F7. ID-1 card size (calibration distance).** Source: https://en.wikipedia.org/wiki/ISO/IEC_7810
- ID-1 is "85.60 by 53.98 millimetres". Used for the card outline in the screen-scale step and as the default distance for the mouse run.

**F8. CSS absolute lengths.** Source: https://www.w3.org/TR/css-values-4/
- "1in = 2.54cm = 96px". Also: "If the anchor unit is the pixel unit, the physical units might not match their physical measurements."
- This sets the default CSS px per mm, and it is why the screen scale is matched to a real card.

**F9. The inch.** Source: https://en.wikipedia.org/wiki/Inch
- "The new standards gave an inch of exactly 25.4 mm".
- Used to convert the nominal 0.014 in and 0.035 in wire diameters (0.3556 mm and 0.889 mm), and the 800 counts-per-inch default.

## Equipment convention

**F12. Three-way stopcock lever.** Source: https://twintreesvet.com/blogs/emergency-procedures-for-vets-techs/how-to-operate-a-3-way-stopcock
- "the direction that the valve is pointing towards always means 'OFF.'" TableView draws each lever pointing at its closed port.
- Search results noted that some brands differ, so this is the common convention, not a universal one.

## Geometry (not a sourced constant)

Roll from fingertip travel, theta = 2·dx/D, follows from rolling without slip: a fingertip that moves dx over a cylinder of radius D/2, turning about its own fixed axis, turns it by dx/(D/2). The expression is geometry. Only the diameters D are inputs.
